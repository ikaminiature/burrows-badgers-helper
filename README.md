# Burrows & Badgers 第2版 ゲーム補助

日本語UIの非公式ゲーム補助PWA。iPhone縦画面を中心に、iPad・PCにも対応する静的Webアプリです。アカウント・バックエンドは不要です。公式の種族・装備・スキル・呪文データは収録せず、手動で入力します。

## 開発

Node.js 24 と Python 3 を使用します。ブラウザは iOS 15.4 以降の Safari または現行の Chrome / Edge / Firefox を想定しています。

```sh
npm ci
npm run dev
```

表示されたサーバーをブラウザで開きます。PWAはHTTPSまたはローカルホストで動作します。iPhoneから開く場合はHTTPSの静的ホスティングを使用してください。

```sh
npm test           # 戦闘ルール・スナップショット独立・復元・移行・アライアンス検証10件＋ビルド検証1件
npm run build      # 公開用 dist/ を生成
```

ブラウザ検証は開発サーバーを別ターミナルで起動して実行します。

```sh
npx playwright install chromium
npm run test:browser
# システムのChromiumを使う場合:
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

`TEST_URL` で検証先を変更できます。テストは新規ブラウザコンテキストを使用し、登録・写真縮小・負傷操作・並び順・状態追加・保存と再読込・JSON復元・オフライン・終了後の基本情報保持を検証します。一時フォルダにバックアップJSONと画面画像を出力します。

## 実装済み

- ホーム、複数ウォーバンドの登録・名前変更・確認付き削除
- キャラクターの登録・編集・複製・確認付き削除・上下移動
- 9能力値のダイス選択（D4 / D6 / D8 / D10 / D12 / D20）、装備・スキル・呪文・メモ
- 写真ライブラリとカメラ入力。長辺800px以下、JPEG品質0.78に縮小
- 登録データを複製してゲーム開始。戦闘状態は基本情報と独立
- 0〜17の負傷、指定のペナルティ、17マスのゲージ、行動済み・戦闘不能・登録順を考慮した整列
- ラウンド更新、戦闘不能からの回復時の行動保持、状態・効果の追加と解除
- IndexedDB自動保存、中断・再開、確認付き終了
- 写真と進行中ゲームを含むJSONバックアップ・復元。復元は全置き換え、入力形式を検証
- Service Workerによるオフライン、マニフェスト、iOS用アイコン、ダークモード

状態・効果の説明は記録のみで、公式ルールを推測して自動適用しません。同時に保持する進行中ゲームは1件です。新規ゲームで置き換える際は確認します。

## ウォーバンドステータス

ウォーバンドを開き「ステータス編集」で、バンド名、レーティング、アライアンス、アーキタイプ、年金、労働力、資材、トレジャリー、メモを入力できます。有効な入力ごとにIndexedDBへ自動保存します。数値は初期値0の手動入力で、自動計算はしません。名前や数値を空欄にした場合は警告を表示して直前の保存値を保持します。

アライアンスは10種類から選択し、アーキタイプを自動設定します（閲覧専用）。未設定・選択肢にない旧アライアンスは「保持」と表示し、ユーザーが選ぶまでは旧アーキタイプも保持します。既知のアライアンスで型が一致しない旧データは、ステータス編集を開いた時に対応する型へ揃えます。進行中ゲームの開始時記録は変更しません。

| アライアンス | アーキタイプ |
| --- | --- |
| 王党派 | 戦士 |
| ならず者 | レンジャー |
| フリービースト | 万能型 |
| キンドレッド | レンジャー |
| ウィッチハンター | 民間呪術師 |
| ワイルドリング | 万能型 |
| アーケイン・コンクラーベ | 民間呪術師 |
| アンデッド | 民間呪術師 |
| 傭兵団 | 戦士 |
| ヒルフォーク | 万能型 |

「隠しておいた装備」「アジト・アップグレード」は独立したリストです。＋で1件ずつ追加し、その欄で直接編集・個別削除できます。入力順を維持し、件数の上限は設けていません。

戦闘画面の「ウォーバンドステータス」では、ゲーム開始時の記録と登録済みバンドの現在の内容を閲覧できます。開始後の登録内容の編集は、進行中ゲームの記録に反映しません。旧ゲームには開始時記録がないため、その旨を表示し、現在の登録内容を閲覧できます。

保存文書・JSONの形式はversion 2です。旧version 1のIndexedDBやJSONは読み込み時に新項目だけを初期化し、既存のキャラクター・写真・負傷・ラウンド・状態効果は維持します。新しいJSONには追加項目と開始時のステータス記録も含まれます。新形式JSONは旧アプリへの復元には対応しません。更新前のバックアップも保管してください。

`npm run test:browser` は既存の戦闘テストに加え、旧IndexedDB/JSON読み込み、ステータス自動保存、両リストの追加・編集・削除・順序、バンド間の分離、新JSON復元、既存データ保持を検証します。

## ウォーバンド詳細とキャラクターカード

一覧から「開く」で、バンド名、レーティング・アライアンス・アーキタイプ、4列の年金・労働力・資材・トレジャリー、装備リスト、アジトリスト、メモ、キャラクター一覧、管理メニューの順に表示します。「ウォーバンド一覧へ」で他のバンドへ移動できます。

キャラクターカードは左に写真とその直下の2桁レベル、右に名前・種族、その下に運命点と経験値を順に表示します。名前の幅を確保し、長い名前は折り返して全文を表示します。閲覧専用のチェックも透明度を下げず、選択済みは濃い色、未選択は背景色と明確な枠線で表示します。能力値は `M S R C F` / `空欄 B N A P` の5列×2段で、ダイスのDを省略します。名前を押すと詳細を開き、そのまま編集できます。既存の複製・並べ替え・削除も利用できます。

運命点・経験値は各0〜5のカウントです。ウォーバンド詳細のカードは閲覧専用です。登録・編集フォームでは変更でき、戦闘画面の変更はゲーム側だけに自動保存します。チェックした位置までを点灯し、チェックを外すとその手前の値になります。旧キャラクターの未設定値は0で補完します。JSONにも保存し、ゲーム終了でリセットしません。既存の戦闘記録には補完や書き換えを行いません。

`npm run test:browser` はカードの配置・長い名前・4桁の4列表示・320px幅、カードの閲覧専用・フォームと戦闘画面の点数変更、再読込、JSON復元、ゲーム終了後の保持も検証します。

## 保存とPWA

保存は端末・ブラウザ・配信元URLごとに独立しています。通常のSafariとホーム画面アプリで保存領域が共有されない場合があります。必要ならJSONで移行してください。容量不足などの保存失敗はヘッダーで通知します。データ削除・端末紛失に備えて、写真付きJSONを定期的に書き出してください。プライベートブラウズでの永続保存は保証されません。

オンラインで初回読み込みを完了すると静的ファイルをキャッシュします。Safariの共有メニューから「ホーム画面に追加」でインストールできます。公開ビルドではファイル内容からService Workerのバージョンを自動生成します。同じ内容なら同じバージョン、ファイルが変われば新しいバージョンになります。IndexedDBは更新で削除しません。

## アプリ内の更新確認

ホームの「最新版を確認」はService Workerの更新処理を使い、HTTPキャッシュを使わずに確認します。最新版なら「現在、最新版です」、オフラインや通信失敗ならその旨を表示します。新しいファイルがインストールされて待機状態になると「更新する」を表示します。iPhoneのホーム画面に追加したPWAでも同じ操作です。

「更新する」でIndexedDBの保存・復元を待ってから待機中Workerを有効化し、制御の切り替わりを確認して再読み込みします。ほかのタブも自分の保存処理を待ってから再読み込みします。保存失敗がある場合は更新・再読み込みを中止するため、JSONバックアップと保存容量の確認を先に行ってください。更新が待機したままなら、全画面を閉じて起動し直す方法も使えます。

この機能を持たない旧版からの最初の移行では、Safari/PWAの画面を一度すべて閉じて再起動してください。以降の更新はアプリ内から操作できます。開発用のソース直配信では `sw.js` のVERSIONを手動で変える必要がありますが、公開用の `npm run build` では自動です。

ブラウザテストには、配信サーバーの実ファイルを切り替える更新試験を含みます。長期HTTPキャッシュ下での更新検出、待機・有効化、保存と復元の完了待ち、別タブ、写真と戦闘記録の保持、オフライン再読込、通信失敗、保存失敗時の更新中止を検証します。実機Safariのインストール済みPWAでの更新操作は端末での確認が必要です。

## GitHub Pages 公開

1. GitHubリポジトリの **Settings → Pages → Source** で **GitHub Actions** を選択します。
2. この変更を `main` に反映します。
3. `Validate and deploy Pages` がテスト・ビルド・`dist/`のデプロイを実行します。

相対パスを使用しているため、`/burrows-badgers-helper/` のようなサブパスに対応します。他のHTTPS静的ホスティングでも `dist/` をそのまま配信できます。PRへのpushだけでは公開されません。mainへマージすると公開ワークフローが実行されます。

## 検証の範囲

クラウド上のChromiumで390×844のモバイル画面の機能を検証しています。実機のiPhone Safariでのカメラ・写真形式（HEIC等）・ホーム画面追加・アプリ終了後の復帰は実機確認が必要です。ブラウザが読み込めない写真形式はエラーを表示します。公式ルールデータの配布や自動判定、複数端末同期、ゲーム履歴の保存は実装対象外です。
